## Outcome
Diagnosed — **source fix required** (a broken relative import). Not applied to source by the deployer; deployer only verified the fix in an ephemeral sandbox.

## Timeline of the two failed runs
1. **run 4323d10f** — failed at `build_image` / `docker-push` with `manifest invalid: Request contains an invalid argument.` This was a **transient registry-side error**: the *identical* image manifest (same digest `sha256:c1711762…`, size 5767) was accepted for the `:latest` tag by step #4 `docker-push-latest` one second earlier, then rejected for the run-id tag by step #3. Not a code or manifest defect. Re-firing the pipeline cleared it.
2. **run 670e7400** (the retry) — push succeeded, build progressed to step #7 `eas-update` (Expo/Metro bundle export) and failed there with a **real source-level defect** (below).

## Root cause (run 670e7400)
Metro export failed resolving an import:

```
> 23 | import { LADDER, LADDER_TYPE } from '../theme/ladder';
Import stack:
  src/components/ladder/LadderButton.tsx  → import "../theme/ladder"
  app/trainer/kyc.tsx → import "../../src/components/ladder/LadderButton"
✖ Export failed
```

`src/components/ladder/LadderButton.tsx` sits one directory level **deeper** than its sibling components. Its import `../theme/ladder` resolves to `src/components/theme/ladder`, which does not exist. The design-system file is at `src/theme/ladder.ts`.

Verified in the sandbox against the run's pulled source:
- OLD `../theme/ladder` (from `src/components/ladder/`) → `src/components/theme/ladder.ts` → **does not exist**
- FIXED `../../theme/ladder` → `src/theme/ladder.ts` → **exists**
- `LADDER` (line 14) and `LADDER_TYPE` (line 80) are both exported from `src/theme/ladder.ts`, so only the path is wrong.

Why the sibling files compiled: `src/components/tabBarStyles.tsx` and `src/components/TrainerBottomSheet.tsx` are at `src/components/`, so their `../theme/ladder` correctly resolves to `src/theme/ladder`. The path was almost certainly copied from one of those into the more deeply-nested `LadderButton.tsx` without accounting for the extra `ladder/` segment. `app/trainer/kyc.tsx` imports `LADDER`/`LADDER_TYPE` correctly via `../../src/theme/ladder`; the fault is entirely inside `LadderButton.tsx`.

## Fix (single line, verified in eph sandbox)
File: `frontend/src/components/ladder/LadderButton.tsx`, line 23

```diff
- import { LADDER, LADDER_TYPE } from '../theme/ladder';
+ import { LADDER, LADDER_TYPE } from '../../theme/ladder';
```
